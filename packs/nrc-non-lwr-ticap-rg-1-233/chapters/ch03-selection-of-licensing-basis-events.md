# Chapter 3: Selection of Licensing Basis Events

Sources: NRC RG 1.233 Rev 0, Guidance for a Technology-Inclusive, Risk-Informed, and Performance-Based Methodology to Inform the Licensing Basis and Content of Applications for Licenses, Certifications, and Approvals for Non-Light Water Reactors, June 2020, ML20091L698; verified via Federal Register notice 85 FR 35339 on 2026-11-13.

## Core Idea

Licensing basis events are the events the method groups into the licensing basis by frequency and consequence insight rather than by inheriting a ready-made light-water reactor event list. The families named at definition depth are anticipated operational occurrences (AOOs), design basis events (DBEs), and beyond design basis events (BDBEs). Design basis accidents (DBAs) are the conservative subset of events carried into deterministic design-basis analysis. Event selection names and groups those events for later stages; event analysis is a separate activity and is not performed in this pack. No numeric frequency threshold, dose value, or frequency-consequence target for any category is on record in this repo and none is stated in this pack.

## Frameworks Introduced

- Frequency-and-consequence grouping. Events enter licensing-basis families through frequency and consequence insight suited to the design, not through an LWR catalog forced onto other technologies.
- Event families at definition depth. AOOs, DBEs, and BDBEs name the licensing-basis event families this stage works with.
- Design basis accidents as subset. DBAs are the conservative subset carried into deterministic design-basis analysis; they are not a fourth independent family invented beside the three.
- Selection versus analysis. This stage selects and groups; it does not analyze sequences, quantify consequences, or issue design verdicts.

## Key Concepts

- Licensing basis event: an event the method places into the licensing basis so later classification and defense-in-depth stages have a defined event set to work from.
- Anticipated operational occurrence (AOO): licensing-basis event family named at definition depth; no frequency bound packaged here.
- Design basis event (DBE): licensing-basis event family named at definition depth; no frequency or consequence bound packaged here.
- Beyond design basis event (BDBE): licensing-basis event family named at definition depth; no frequency or consequence bound packaged here.
- Design basis accident (DBA): conservative subset of events carried into deterministic design-basis analysis.
- Frequency and consequence insight: the basis for grouping, not an LWR inheritance rule and not a packaged numeric target.
- Technology-inclusive selection: non-LWR designs do not inherit a ready-made LWR event list; selection follows the design and its risk picture at outline depth.
- Fence: no numeric frequency threshold, dose value, or frequency-consequence target for any category is on record in this repo and none is stated in this pack.

## Mental Models

Picture a sorter, not a calculator. Events arrive with frequency and consequence insight; the sorter places them into AOO, DBE, or BDBE families and marks the DBA subset for deterministic design-basis analysis. The sorter does not invent an LWR event list for a non-LWR plant, and it does not run the analysis those events later receive. Numbers that would draw family boundaries stay off this page because none are on record here.

## Anti-patterns

Treating this chapter as an event-selection procedure or analysis runbook is the named anti-pattern: the chapter names families and the selection idea only. A companion error is importing an LWR event list and calling the result technology-inclusive selection. A third error is stating or implying numeric frequency thresholds, dose values, or frequency-consequence targets for any family. A fourth error is treating event selection as event analysis, or answering which events a named design must carry.

## Key Takeaways

- Licensing basis events are grouped by frequency and consequence insight into AOOs, DBEs, and BDBEs.
- Design basis accidents are the conservative subset carried into deterministic design-basis analysis.
- Selection is not inheritance of an LWR event list and is not event analysis.
- No numeric frequency threshold, dose value, or frequency-consequence target for any category is packaged here.
- No event analysis is performed and no design event set is chosen in this pack.
