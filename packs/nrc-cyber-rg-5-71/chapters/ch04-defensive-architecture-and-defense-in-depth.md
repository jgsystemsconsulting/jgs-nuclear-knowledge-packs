# Chapter 4: Defensive architecture and defense in depth

Sources: NRC RG 5.71 Rev. 1, Cyber Security Programs for Nuclear Power Reactors, February 2023, ML22258A204; pin 2026-11-08 (P9 VERIFY cleared).

## Core Idea

RG 5.71 describes a defensive architecture built from mutually reinforcing defensive layers and defensive controls across the systems and networks the regulation covers. That is the framework statement, and this chapter carries it as descriptive orientation: what the guide says the architecture is built from, stated at framework level and nothing further.

## Frameworks Introduced

- Mutually reinforcing layers. The architecture is described as defensive layers that reinforce one another; the pack states the description and no design.
- Defensive controls across the covered estate. The layers and controls span the systems and networks 10 CFR 73.54 covers; the coverage statement connects ch02's protection scope to this architecture description.

## Key Concepts

- Defensive architecture: the guide's description of how a program's protections are arranged; a description, not a design.
- Mutually reinforcing defensive layers: the architecture's building blocks as the guide frames them.
- Defensive controls: named as categories only; never products, configurations, detection logic, or tuning.
- Coverage frame: the systems and networks the regulation covers, which ch02 orients.

## Mental Models

Read the architecture as a description of an arrangement, not a blueprint for one: layers reinforce each other, controls are categories, and the arrangement spans the systems and networks the regulation covers. The words carry the framework; no diagram, no design, no site drawing lives here.

## Anti-patterns

Reading this chapter as an architecture prescription for a real site is the chapter's named anti-pattern. This is descriptive orientation only: program specifics for any named site are beyond public text and beyond this pack, and no sentence here is a design instruction.

## Key Takeaways

- RG 5.71 describes a defensive architecture built from mutually reinforcing defensive layers and defensive controls.
- The layers and controls span the systems and networks the regulation covers.
- Controls are named as categories only in this pack.
- The description is framework-level; no architecture prescription for any site appears here.
