# Chapter 2: Adequacy relative to the application

Sources: NRC RG 1.200 Rev. 3, Acceptability Probabilistic Risk Assessment Results Risk-Informed Activities, December 2020, ML20238B871; listing-page pin 2026-11-08, re-checked 2026-11-11.

## Core Idea

The adequacy question is application-relative. Adequacy is judged against the named application the PRA supports, so an adequacy answer that does not name its application answers nothing. The same PRA can be adequate for one application and not another, and a judgement made for one application does not transfer to another decision unlabeled.

## Frameworks Introduced

- The scoped judgement: every adequacy claim in this pack names the application and the decision the PRA would inform, per ch01; the claim is about that use, and about nothing wider.
- The transfer rule: carrying an adequacy conclusion to a second decision requires naming the change of use and re-asking the question; nothing transfers unlabeled.

## Key Concepts

- Application: the named risk-informed activity and the decision the PRA results would inform; adequacy is judged against it, so the answer names it first.
- Adequate for one use and not another is an expected outcome, not a contradiction, because the judgement tracks the use rather than the PRA alone.
- An unlabeled adequacy statement is incomplete rather than wrong: it lacks the scope that would make it checkable against anything.
- The scoping habit keeps answers small: an adequacy claim is as wide as its named application and no wider.

## Mental Models

Read an adequacy claim as a pair: the judgement plus the named application it is scoped to. Drop the second half and the claim cannot be weighed, because there is nothing to judge it against.

## Anti-patterns

Blanket good-enough verdicts detached from any use are the named anti-pattern: this pack issues no such verdict, for any PRA. A companion error is carrying a judgement from one decision into another without naming the change of use; if the use changes, the question is asked again.

## Key Takeaways

- Adequacy is judged against the named application the PRA supports.
- The same PRA can be adequate for one application and not another.
- No adequacy conclusion transfers to another decision unlabeled; a change of use re-opens the question.
